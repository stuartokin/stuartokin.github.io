## 1. What the site is

`https://horizonqltd.com/` — the GitHub Pages "user site" for the `stuartokin` account (repo
`stuartokin.github.io`), titled **HorizonQ Observatories**. One page that lists Stuart's public
boards and apps (each in its own repo, served at `https://horizonqltd.com/<repo>/`) with:

- a card per board: still image, 8-second hover preview, **Watch demo** (full video in a pop-up
  player), **Open** (goes to the board), optional **in ARTICLE** badge (his LinkedIn article),
  "Updated N days ago" (from GitHub);
- two views: **Tiles** (grouped into sections) and **Carousel** (a 3D ring drawn with WebGL);
- **Fit to screen** (everything on one screen), **text size** (tiles only), **music**, **dark/light**;
- an ⓘ panel by the title with GitHub + LinkedIn links and the page version.

### Custom domain (from 2026-11-16)

- `CNAME` in the repo root holds `horizonqltd.com`; GitHub Pages serves the site there and
  redirects `stuartokin.github.io/...` (and every project repo's `stuartokin.github.io/<repo>/`)
  to the same path on the domain. Old links keep working.
- DNS is at **GoDaddy** (Stuart's account): four `A` records for `@` → `185.199.108.153`,
  `.109.153`, `.110.153`, `.111.153`; `CNAME www` → `stuartokin.github.io`; a `TXT`
  `_github-pages-challenge-stuartokin` record for GitHub domain verification. **Never touch the
  MX / SPF / DKIM / DMARC / autodiscover records** — they carry his email.
- Repo settings → Pages: custom domain `horizonqltd.com`, **Enforce HTTPS** on.
- `"base"` in `boards.json` builds the card links; the og:image in `tools/page.html` and the
  rig (`tests/check.js` reads `base`) follow it.
- The kill switch is read from `raw.githubusercontent.com`, so the domain doesn't affect it.

## 3. How the page is built

`python3 tools/build.py` reads `tools/page.html`, replaces:

| placeholder | becomes |
|---|---|
| `<!--SECTIONS-->` | one `<section class="group">` per section in `boards.json`, each with its cards |
| `<!--COUNT-->` | number of boards (in the "N boards · …" line) |
| `__VER__` | contents of `tools/VERSION` (ⓘ panel text and `?v=` on css/js URLs) |

…and writes `index.html` at the repo root. It validates first (missing fields, unknown section,
media files not found, bad dates) and refuses to build if anything is wrong.
`--bump` moves the version on: same day → next letter (`…13g` → `…13h`), new day → `<today>a`.

Script loading at the bottom of the page: `js/site.js` (classic script, runs first and exposes
`window.HQ`), then `js/carousel3d.js` (module, runs after, exposes `window.HQ3D`).
A tiny inline script in `<head>` applies the saved theme, text size and the `lite` class
before first paint, so nothing flashes.

Rules the build relies on:
- A section with exactly one card makes that card **wide** (picture left, text right) in tiles.

  11 boards + 1-hour cache stays well inside.
- Strip LinkedIn share-tracking (`?utm_source=…`) from article URLs.

## 6. Behaviour, feature by feature

All in `js/site.js` unless noted. `window.HQ` exposes `{cards, stage, getAngle, frontIndex, step, refresh, layoutOrbit, isFocused}` for the 3D module.

**Views.** `setView('tiles'|'carousel')` moves the *same* card elements between their section
grids, `#fitgrid`, and the carousel ring. First visit: carousel if `min(innerWidth, screen.width) ≥ 600`
(tablets, open Fold, laptops), tiles on phones. Then remembered.

**Fit to screen.** `scaleToFit()` binary-searches a CSS `zoom` for `.wrap` so the page's height
fits the window exactly. `zoom` (not `transform: scale`) is used because it re-lays the page at
the new size, so it always spans the full screen width and never makes the page wider than the
screen. Can go above 1 on big screens. In tiles it also tries 1…N columns and keeps the layout
whose cards come out largest. Phones and short screens use a row layout (picture left).

**Toolbar.** Never wraps. `fitBar()` adds classes step by step while it overflows: `compact`
(icons only) → `tight` (hide "100%") → `tiny` (tighter spacing). Re-checked by a ResizeObserver.
In fit mode it is fixed at `compact tight` to avoid a resize loop.

**Text size.** A− / A+ steps through 85–175% via `--ts`; only tiles use it. Hidden in carousel.

**Music.** `media/music.mp3` (Mixkit "Driving Ambition", same track as ResearchGap), 35% volume,
off by default (browsers block sound until a tap). Remembered; if remembered "on", starts on the
first tap/click. Pauses while the demo player is open.

**Demo player.** Native `<dialog>`. Tabs when a board has several videos (Q-Day Research: Full demo / Intro).
Escape, Close or the backdrop close it.

**Hover previews.** Desktop only (`hover: hover` + fine pointer), and not under reduced motion:
the 8-second loop fades in over the still. In the carousel only the front card previews.

**Updated labels.** See boards.json above. The header line shows "N boards · M maintained by
agents · last change X" (M counts live cards without a custom `tag`).

**Info panels.** Title ⓘ toggles `.hinfo`; closes on outside click or Escape. Section ⓘ buttons
(below 1024px) toggle the section notes. The header sits at `z-index: 60` so the panel opens
above the sticky toolbar.

**Resize.** On touch devices, height-only changes under 160px (the address bar sliding in/out)
are ignored — re-laying the page for those made the footer flicker on the Fold.

## 7. The 3D carousel (WebGL)

`js/carousel3d.js`, three.js r170. The page (`site.js`) owns the state (angle, front card,
focus); the module only draws and reports positions back:

```
window.HQ3D = { ready, update(angle, front, instant, focusing), resize(), pick(x, y) → index|-1, frontRect() → DOMRect-like }
```

- **Cards** are extruded rounded rectangles (1 × 1.6 units), thickness 0.08 (dark) / 0.11 (light).
  Their front faces are **canvas textures painted from each card's own HTML** (picture, badges,
  tag, title, description, Open) — so editing `boards.json` updates the 3D cards automatically.
  Repainted when fonts load and when the theme changes.
- **Ring:** radius `R = (0.5 / tan(π/N)) × 1.3`; each card sits at its angle on the rim and is
  turned 38% of the way back towards the viewer. Camera ~0.25 rad above horizontal; `frame()`
  binary-searches the camera distance so the ring and platform fill the stage, then centres it.
- **Platform:** a cylinder (radius 1.22R, height 0.2) with a textured top, an engraved inner ring,
  a thin rim (torus) and a soft shadow plane; dark mode adds a teal centre glow.
- **Front card emphasis:** a spotlight (cone beam + pool of light + a real SpotLight), the front
  card lifts 0.13 and steps forward 0.18, its edges glow brighter; all fade smoothly with
  "how in front" a card is while turning. Others dim (`--dim`-style colour multiply).
- **First-visit hint:** "Click to open" / "Tap to open" pill under the front card, until the
  visitor first opens a card (`obs.opened`).
- **Theme:** dark = teal glass edges + teal rim; light = stone edges + white rim. A
  MutationObserver on `data-theme` rebuilds materials.
- **Rendering on demand:** frames are drawn only while something is moving.
- **Fallback:** if WebGL can't start, or the context is lost, the module removes itself and the
  older CSS 3D carousel (`.oring`, styles in site.css, `lite` flat variant on touch) takes over.
  The rig checks this.
- The text on the back cards is part of a picture (not live text); only the enlarged front card
  (below) is real HTML.

**The enlarged front card ("float card").** Pause ~0.4 s on the front card (mouse), tap it
(touch), or Tab to it: `focusFront(true)` clones the card's HTML into a fixed-position
`.card.ofloat` laid **over** the carousel (outside the 3D scene), sized up to 1.75× (max 640px),
never wider than the screen, never above the toolbar or below the bottom edge. It grows out of
the front card's on-screen rectangle (`HQ3D.frontRect()`). Leaving it, turning the ring,
scrolling, Escape or a tap elsewhere closes it.

### The lens (beam source)

`fitLens()` in `carousel3d.js` runs after every framing. It projects the lens (`LENS_Y = CH + 1.0`,
radius `LENS_R`) to the screen and shows it only if it sits between the two `.tbgroup` toolbars
(24 px clear each side) and its body touches no header text (measured per text run, not per box).
Then the canvas is made taller by `E` px upwards (`top: -E`), `camera.setViewOffset` extends the
view so the ring stays put, and `.ostage.lens` lets the stage overflow upwards. If it doesn't fit,
the beam goes back to fading out above the cards (top at `CH + 1.9`). Side cards in the dark
theme dim as `min(0.8, 0.32 + angle/180)`, times 0.9.

## 8. Touch, phones and the Fold

This is where most bugs have been. Current handling:

- **Drag threshold**: a pointer must move 5px (mouse), 14px (finger) or 24px (finger starting on
  the float card) before it counts as spinning the ring. Real taps wobble.
- **Float card taps fire on `pointerup`**, not on the browser's `click` (which a wobbly tap can
  cancel), then run 60 ms later so the browser's own click can't land on the player backdrop.
- **`passThrough`**: when the float card forwards "Watch demo" to the ring card, the carousel's
  own click handler must ignore it (otherwise it re-opens the float card).
- **`.card.ofloat { touch-action: none }`** so a wobbly tap isn't taken as a scroll.
- **Pointer moves are tracked on `window`** during a drag so a drag that starts on the float card
  or leaves the stage still turns the ring.
- **`html, body { overflow-x: clip }`** and fit mode never widens the page — a page wider than
  the screen makes phone browsers zoom out and everything looks broken.
- **Touch screens get solid (not blurred) toolbars** — `backdrop-filter` + sticky + 3D glitched in Edge.
- Samsung Galaxy Z Fold sizes used in testing: folded 344×882, open 884×1104, sideways 1104×884.

## 11. Making demo videos

Each card needs `media/<name>.jpg` (1280×720 still), `media/<name>-preview.mp4` (8 s, 640 wide,
silent loop) and one or more `media/<name>.mp4` (1280 wide, H.264, `+faststart`; silent unless
the sound matters — Q-Day, AI Model Cortex, Starlane and Apollo keep theirs). Stuart's square
LinkedIn videos (1080×1080) go in as they are: the player letterboxes them, and the card keeps its
own 16:9 still and preview (a 16:9 crop of a square video would cut off its captions).

**From Stuart's screen recording** (best for apps that need live data or the internet):
`tools/make_media.sh <name> <recording> "<keep ranges>" <preview-start> <still-at>`.
To find pauses worth cutting, measure motion per second (frames that barely change = pause):

```bash
ffmpeg -i rec.mp4 -vf "fps=4,scale=240:-1,format=gray" f/%04d.png
python3 - <<'EOF'
from PIL import Image, ImageChops, ImageStat; import glob
fs=sorted(glob.glob('f/*.png')); prev=None; sec={}
for i,f in enumerate(fs):
    im=Image.open(f)
    if prev: sec.setdefault(i//4,[]).append(ImageStat.Stat(ImageChops.difference(im,prev)).mean[0])
    prev=im
print(' '.join(f'{s}:{max(v):.1f}' for s,v in sorted(sec.items())))   # ~0.5 = still
EOF
```
…then confirm with a timestamped contact sheet:
`ffmpeg -i rec.mp4 -vf "fps=1/3,scale=560:-1,drawtext=text='%{pts\:hms}':x=6:y=6:fontsize=26:fontcolor=yellow:box=1,tile=4x7" -frames:v 1 sheet.jpg`
(keep the "thinking" parts short, cut loading flashes and the idle end).

**Scripted recording with Playwright** (works for static boards with no live data): serve the
board's repo locally (`python3 -m http.server`), open it in a `recordVideo` browser context at
1600×900 with a visible cursor overlay, script the clicks with short pauses, then trim/encode
with ffmpeg. Quantum Observatory must be built first (`npm install && npx vite build
--base=/quantum-observatory/`). Boards that fetch data from the internet (Energy Resilience,
Cyber Attack Earth's live feeds, map tiles) can't be recorded faithfully offline — ask Stuart
for a screen recording instead.

## 13. Testing

## 14. Releasing

1. Make the change (boards.json / page.html → build; or css/js directly).
2. `python3 tools/build.py --bump` (also refreshes `status.json`; needs the internet, keeps the
   old file if offline; `--no-status` skips it)
3. `cd tests && npm test` → all PASS; `npm run shots` and look.
4. Add an entry to `docs/CHANGELOG.md`.
5. Commit and push to `main` (backup tag first if major; see `docs/STANDARDS.md`).
6. Tell him the new version string so he can confirm it in the ⓘ panel on each device.

## 14b. First paint

The inline script in the page head picks the first view with the same rule as `setView`
(saved choice, else carousel from 600 px wide). For the carousel it adds `boot-carousel` to `<html>`
(hides tiles and footer; `site.js` removes it right after the first `setView`) and, if the browser
has WebGL, `gl-wait` (hides the CSS ring; `carousel3d.js` removes it when ready or when WebGL fails;
`site.js` removes it after 5 s as a safety net).

## 14c. Front board, memory and shareable links

- First visit: the carousel opens on `DEFAULT_FRONT` (`'ResearchGap'`, in `site.js`).
- `obs.front` (localStorage) remembers the repo of the board in front; written by `noteFront()`
  whenever the front changes in the carousel (not during a drag).
- A board's **slug** is its title, lower case, apostrophes dropped, other runs of non-letters as `-`
  (`the-shrinking-gap`, `apollos-maths-missions`). `#<slug>` or `#<repo>` in the URL wins over the
  remembered board. In the carousel the ring turns to it; in tiles the card scrolls into view and
  glows (`.card.target`) for 2.6 s. `hashchange` does the same while the page is open.
- The address bar follows the carousel (`history.replaceState`, so Back isn't filled with turns).
- The status panel's "Copy link" box gives `https://stuartokin.github.io/#<slug>`. For LinkedIn
  articles, paste that link.

## 14d. Hidden cards (key to unlock)

A hidden card (none at present; Energy Resilience was hidden 16–17 Nov 2026, now restricted, §14e) is never
written into `index.html`, the card count or `status.json`.

- **Where it lives (since 20 Nov 2026).** In the **`HUB_HIDDEN_CARDS`** GitHub secret, never in `boards.json`.
  `boards.json` is public (on GitHub and at horizonqltd.com/tools/boards.json), so a card kept there could be
  read without the key; a security review found that, and the git history still holds the old Energy
  Resilience card text. `build.py` and `seal.py` refuse a `"hidden": true` card in `boards.json`.
  - The secret is a JSON list of cards written exactly like those in `boards.json`, plus an optional
    `"after": "<repo>"` naming the visible card it follows (otherwise the end of its section). Example:
    `[{"sec": "live", "after": "energy-resilience", "repo": "…", "title": "…", "media": "…", "topic": "…",
    "fallback": "2026-11-20", "videos": [{"label": "Walkthrough", "media": "…"}], "desc": "…"}]`
  - To add or change one: Stuart pastes the list into Settings → Secrets and variables → Actions →
    `HUB_HIDDEN_CARDS`, then runs Actions → Seal hidden cards → Run workflow. Claude can't set secrets.
  - Its media files in `media/` are public too: give them names that don't give the card away.

- **Sealing.** `tools/seal.py` renders it with `build.card()`, adds where it goes (its section and the
  visible card it follows) and encrypts that with AES-256-GCM, under a key derived from the
  `HUB_UNLOCK_KEY` secret (PBKDF2-SHA256, 600,000 rounds). The result goes in `sealed.json`.
  - The workflow `.github/workflows/seal.yml` runs it on pushes that change the cards, and by hand.
    Run it by hand after adding or changing the secret.
  - While the key is unchanged the salt is kept, so a card edit doesn't lock out devices.
  - No key set: `{"sealed": false}`, and the card stays hidden for everyone.
- **Unlocking.** `js/unlock.js` loads before `site.js`. If this device holds the unlock, it decrypts
  `sealed.json`, inserts the card in its place, and then starts `site.js` and the carousel, so tiles,
  carousel, counts and links all treat it like any other card.
  - Unlock with the key field in the ⓘ panel, or a link ending `#key=…`. The key is wiped from the
    address at once, and a link pasted into an open tab works too.
  - The device stores the derived AES key and salt (`obs.unlock`), not the key itself. "Lock" in the
    ⓘ panel forgets it; a new key makes stored unlocks stop fitting.
- **Limits.** This hides the card from the hub only.
  - The board itself is still public at its own address and on GitHub, and its media files are still
    in `media/`.
  - The sealed file is public, so a short key could be guessed offline: use a long random key (a password
    manager's 20+ characters, or five or more random words).
  - A `#key=` link stays in the browser history and in wherever it was sent: change the key after sharing one.
  - Every board shares the horizonqltd.com address, so a fault in one board's page could read another's stored
    unlock. Keep boards free of third-party scripts.
- **Rig.** `tests/check.js` seals a made-up card (`tests/lib/hidden-test.json`) with a made-up key, so these
  checks run every time, not only when a card is hidden. It also checks `boards.json` holds no hidden card and
  that `build.py` and `seal.py` refuse one. It checks:
  - the card isn't in the page or its source without the key
  - a wrong key shows nothing
  - the link unlocks, wipes the key, places the card and survives a reload
  - a link pasted into an open tab works
  - the ⓘ field works and Lock re-hides the card

## 14e. Restricted cards (access by request)

**Since 2026-11-19 (sign-in):** Energy Resilience uses `"restricted": { "email": "…", "signin": "https://energy.horizonqltd.com/api/me" }` with `"url": "https://energy.horizonqltd.com/"`. The card fetches that address with `credentials: 'include'` (same parent domain, so the Cloudflare Access cookie goes along; the board's Worker allows credentials for horizonqltd.com). An answer with an email opens the card and puts **Sign out** in the ⓘ panel; anything else (Access redirects) leaves it dimmed. Badge "🔒 Sign in · by invitation", link text "Invited? Sign in". The board's own docs: energy-resilience `docs/CLOUDFLARE-MIGRATION.md`.

Earlier (17–19 Nov), and still supported for other boards: `"restricted": { "email": "…", "keydb": "er-seal" }` in `boards.json`.
The card is on the page and in the counts, but shown dimmed until this device has opened the board itself.
- **Build** (`tools/build.py`): class `card--restricted`, `data-keydb`, a "🔒 Access by request" badge on the
  picture, a "Request access" mailto button, and "Have a key? Open ↗" (the normal label is in `data-open`).
- **Look** (`css/site.css`, end): picture blurred and darkened, summary softened, Watch demo hidden. The 3D
  carousel (`carousel3d.js` `paintFace`) blurs the picture and summary and draws the badge; the enlarged front
  card copies the class (`site.js`).
- **Clicks** (`site.js`): the picture opens the board (its key screen), not the video; no hover preview.
- **Turning clear** (`js/access.js`): the board at `/<repo>/` shares this site's address, so its key store
  (IndexedDB named in `data-keydb`, value `raw`) is readable here. If present and it still fits the board's
  `seal.json` check, the card's class is removed and the carousel repainted. Nothing is sent anywhere.
- **Locking again** (`access.js`): on an unlocked device the ⓘ panel shows "🔓 <title> open on this device ·
  Lock". Lock deletes `raw` and `raw2` from the board's key store and unregisters the board's service worker,
  then reloads: card dimmed, board back to its key screen. (Or visit `/<repo>/?lock`.) The hub key field in
  the ⓘ panel only appears when a card is hidden (§14d).
- **Limits:** the dimming is presentation, not protection. The board protects itself with its keys; its media
  files in `media/` are public.
- **Status:** restricted (and hidden) cards stay out of `status.json`.
- **Rig** (`tests/check.js`, "restricted laptop/phone"): fakes the board's `seal.json` and key store.

**Kill switches.** `automation.json` (`{"paused": false}`) here is the master; each repo above
has its own `automation.json`. Every automatic workflow starts with a `switch` job that reads
both (master from `raw.githubusercontent.com/stuartokin/stuartokin.github.io/main/…`, local at
the run's commit). If either says `true`, runs started by a schedule, issue, comment or another
workflow stop there and change nothing (a notice says which switch). Runs started by hand
("Run workflow") and pushes always go ahead. If the master file can't be read, the run carries on
with a warning. ResearchGap's own `AGENTS_ENABLED` / `UI_AGENT_ENABLED` variables still apply on
top. Any new scheduled or agent workflow must copy the `switch` job.

**Status dot.** `tools/status.py` reads, per card: workflows with a schedule or issue trigger,
their latest runs (and whether the work jobs actually ran or were skipped), both switches, the
last commit, a version (`version.json` → `VERSION` → `package.json` → `CHANGELOG.md` →
`APP_VERSION` in index.html / `data-rN` tags), and who made the last 30 commits:
- **agent**: AI agents on their own (`horizonq-agent`, `research-gap-*`, "agent-merged",
  "AI-maintained", "Data revision", `scout:` etc.)
- **assistant**: Claude in a session Stuart started (author "Claude" or a `Co-Authored-By: Claude`
  / `Claude-Session:` trailer)
- **script**: bots with no AI (`data-pack-bot`, `app-build`, `github-actions[bot]`)
- **you**: everything else, i.e. Stuart, including web uploads of code an AI helped write.

States: `on` (green, pulses), `paused` (amber), `failed` (red, last run failed), `none` (grey,
"Manual"). `build.py` writes each card's state into the page from `status.json`; `site.js`
fetches the latest `status.json` (10-minute cache-buster), updates the dots and "Updated" dates,
and repaints the WebGL faces (`HQ3D.repaint()`). The pill is a `<button class="stat">` beside
the picture (not inside the `.media` button or the `.body` link); clicks are delegated from the
document, so the enlarged carousel copy works too (its pointerup handler includes `.stat`).
The panel is `<dialog id="statDlg">`, filled by `statusHtml()` in `site.js`.
