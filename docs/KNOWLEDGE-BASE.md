## 1. What the site is

`https://stuartokin.github.io/` — the GitHub Pages "user site" for the `stuartokin` account,
titled **HorizonQ Observatories**. One page that lists Stuart's public boards and apps
(each in its own repo, served at `https://stuartokin.github.io/<repo>/`) with:

- a card per board: still image, 8-second hover preview, **Watch demo** (full video in a pop-up
  player), **Open** (goes to the board), optional **in ARTICLE** badge (his LinkedIn article),
  "Updated N days ago" (from GitHub);
- two views: **Tiles** (grouped into sections) and **Carousel** (a 3D ring drawn with WebGL);
- **Fit to screen** (everything on one screen), **text size** (tiles only), **music**, **dark/light**;
- an ⓘ panel by the title with GitHub + LinkedIn links and the page version.

Tagline: *"Research boards on cyber, quantum, cryptography, and AI. Every claim carries its
source, its date, and whether anyone has actually checked it."*

## 3. How the page is built

`python3 tools/build.py` reads `tools/page.html`, replaces:

| placeholder | becomes |
|---|---|
| `<!--SECTIONS-->` | one `<section class="group">` per section in `boards.json`, each with its cards |
| `<!--COUNT-->` | number of boards (in the "N boards · …" line) |
| `__VER__` | contents of `tools/VERSION` (ⓘ panel text and `?v=` on css/js URLs) |

…and writes `index.html` at the repo root. It validates first (missing fields, unknown section,
media files not found, bad dates) and refuses to build if anything is wrong.
`--bump` moves the version on: same day → next letter (`…13g` → `…13h`), new day → `<today>a`.

Script loading at the bottom of the page: `js/site.js` (classic script, runs first and exposes
`window.HQ`), then `js/carousel3d.js` (module, runs after, exposes `window.HQ3D`).
A tiny inline script in `<head>` applies the saved theme, text size and the `lite` class
before first paint, so nothing flashes.

## 4. boards.json

```jsonc
{
  "base": "https://stuartokin.github.io/",
  "sections": [ { "key": "live", "label": "Live · maintained by agents and live data", "note": "…" }, … ],
  "boards": [
    {
      "sec": "live",                       // which section: live | studies | fun
      "repo": "energy-resilience",         // GitHub repo; card links to base + repo + "/"
      "url": "https://…",                  // optional: link somewhere other than base + repo
      "title": "Energy Resilience",
      "media": "energy-resilience",        // media/<media>.jpg and media/<media>-preview.mp4
      "topic": "Energy · resilience",      // small caps label next to the tag
      "tag": "Live data",                  // optional: replaces the "Live" badge text; such
                                           //   cards are NOT counted as "maintained by agents"
      "lead": true,                        // optional: accent border (Quantum Observatory)
      "go": "Play",                        // optional: button text instead of "Open"
      "fallback": "2026-11-12",            // date shown if GitHub can't be reached
      "videos": [ { "label": "Walkthrough", "media": "energy-resilience" } ],
                                           // one or more → tabs in the player; media/<media>.mp4
      "article": { "title": "…", "url": "https://www.linkedin.com/pulse/…" },   // optional
      "desc": "One or two sentences.",
      "note": "…",                          // optional: dashed callout on the card
      "about": "Long description …"         // optional: shown under the video in the player
    }
  ]
}
```

Rules the build relies on:
- A section with exactly one card makes that card **wide** (picture left, text right) in tiles.
- The "Updated N days ago" label asks the GitHub API for the repo's latest commit
  (`/repos/stuartokin/<repo>/commits?per_page=1`), cached for an hour per visitor. Starlane and
  Apollo cards point at their own repos. Unauthenticated limit is 60 requests/hour per IP, which
  11 boards + 1-hour cache stays well inside.
- Strip LinkedIn share-tracking (`?utm_source=…`) from article URLs.

## 6. Behaviour, feature by feature

All in `js/site.js` unless noted. `window.HQ` exposes `{cards, stage, getAngle, frontIndex, step, refresh, layoutOrbit, isFocused}` for the 3D module.

**Views.** `setView('tiles'|'carousel')` moves the *same* card elements between their section
grids, `#fitgrid`, and the carousel ring. First visit: carousel if `min(innerWidth, screen.width) ≥ 600`
(tablets, open Fold, laptops), tiles on phones. Then remembered.

**Fit to screen.** `scaleToFit()` binary-searches a CSS `zoom` for `.wrap` so the page's height
fits the window exactly. `zoom` (not `transform: scale`) is used because it re-lays the page at
the new size, so it always spans the full screen width and never makes the page wider than the
screen. Can go above 1 on big screens. In tiles it also tries 1…N columns and keeps the layout
whose cards come out largest. Phones and short screens use a row layout (picture left).

**Toolbar.** Never wraps. `fitBar()` adds classes step by step while it overflows: `compact`
(icons only) → `tight` (hide "100%") → `tiny` (tighter spacing). Re-checked by a ResizeObserver.
In fit mode it is fixed at `compact tight` to avoid a resize loop.

**Text size.** A− / A+ steps through 85–175% via `--ts`; only tiles use it. Hidden in carousel.

**Music.** `media/music.mp3` (Mixkit "Driving Ambition", same track as ResearchGap), 35% volume,
off by default (browsers block sound until a tap). Remembered; if remembered "on", starts on the
first tap/click. Pauses while the demo player is open.

**Demo player.** Native `<dialog>`. Tabs when a board has several videos (Q-Day Research: Full demo / Intro).
Escape, Close or the backdrop close it.

**Hover previews.** Desktop only (`hover: hover` + fine pointer), and not under reduced motion:
the 8-second loop fades in over the still. In the carousel only the front card previews.

**Updated labels.** See boards.json above. The header line shows "N boards · M maintained by
agents · last change X" (M counts live cards without a custom `tag`).

**Info panels.** Title ⓘ toggles `.hinfo`; closes on outside click or Escape. Section ⓘ buttons
(below 1024px) toggle the section notes. The header sits at `z-index: 60` so the panel opens
above the sticky toolbar.

**Resize.** On touch devices, height-only changes under 160px (the address bar sliding in/out)
are ignored — re-laying the page for those made the footer flicker on the Fold.

## 7. The 3D carousel (WebGL)

`js/carousel3d.js`, three.js r170. The page (`site.js`) owns the state (angle, front card,
focus); the module only draws and reports positions back:

```
window.HQ3D = { ready, update(angle, front, instant, focusing), resize(), pick(x, y) → index|-1, frontRect() → DOMRect-like }
```

- **Cards** are extruded rounded rectangles (1 × 1.6 units), thickness 0.08 (dark) / 0.11 (light).
  Their front faces are **canvas textures painted from each card's own HTML** (picture, badges,
  tag, title, description, Open) — so editing `boards.json` updates the 3D cards automatically.
  Repainted when fonts load and when the theme changes.
- **Ring:** radius `R = (0.5 / tan(π/N)) × 1.3`; each card sits at its angle on the rim and is
  turned 38% of the way back towards the viewer. Camera ~0.25 rad above horizontal; `frame()`
  binary-searches the camera distance so the ring and platform fill the stage, then centres it.
- **Platform:** a cylinder (radius 1.22R, height 0.2) with a textured top, an engraved inner ring,
  a thin rim (torus) and a soft shadow plane; dark mode adds a teal centre glow.
- **Front card emphasis:** a spotlight (cone beam + pool of light + a real SpotLight), the front
  card lifts 0.13 and steps forward 0.18, its edges glow brighter; all fade smoothly with
  "how in front" a card is while turning. Others dim (`--dim`-style colour multiply).
- **First-visit hint:** "Click to open" / "Tap to open" pill under the front card, until the
  visitor first opens a card (`obs.opened`).
- **Theme:** dark = teal glass edges + teal rim; light = stone edges + white rim. A
  MutationObserver on `data-theme` rebuilds materials.
- **Rendering on demand:** frames are drawn only while something is moving.
- **Fallback:** if WebGL can't start, or the context is lost, the module removes itself and the
  older CSS 3D carousel (`.oring`, styles in site.css, `lite` flat variant on touch) takes over.
  The rig checks this.
- The text on the back cards is part of a picture (not live text); only the enlarged front card
  (below) is real HTML.

**The enlarged front card ("float card").** Pause ~0.4 s on the front card (mouse), tap it
(touch), or Tab to it: `focusFront(true)` clones the card's HTML into a fixed-position
`.card.ofloat` laid **over** the carousel (outside the 3D scene), sized up to 1.75× (max 640px),
never wider than the screen, never above the toolbar or below the bottom edge. It grows out of
the front card's on-screen rectangle (`HQ3D.frontRect()`). Leaving it, turning the ring,
scrolling, Escape or a tap elsewhere closes it.

## 8. Touch, phones and the Fold

This is where most bugs have been. Current handling:

- **Drag threshold**: a pointer must move 5px (mouse), 14px (finger) or 24px (finger starting on
  the float card) before it counts as spinning the ring. Real taps wobble.
- **Float card taps fire on `pointerup`**, not on the browser's `click` (which a wobbly tap can
  cancel), then run 60 ms later so the browser's own click can't land on the player backdrop.
- **`passThrough`**: when the float card forwards "Watch demo" to the ring card, the carousel's
  own click handler must ignore it (otherwise it re-opens the float card).
- **`.card.ofloat { touch-action: none }`** so a wobbly tap isn't taken as a scroll.
- **Pointer moves are tracked on `window`** during a drag so a drag that starts on the float card
  or leaves the stage still turns the ring.
- **`html, body { overflow-x: clip }`** and fit mode never widens the page — a page wider than
  the screen makes phone browsers zoom out and everything looks broken.
- **Touch screens get solid (not blurred) toolbars** — `backdrop-filter` + sticky + 3D glitched in Edge.
- Samsung Galaxy Z Fold sizes used in testing: folded 344×882, open 884×1104, sideways 1104×884.

## 11. Making demo videos

Each card needs `media/<name>.jpg` (1280×720 still), `media/<name>-preview.mp4` (8 s, 640 wide,
silent loop) and one or more `media/<name>.mp4` (1280 wide, H.264, `+faststart`; silent unless
the sound matters — Q-Day and AI Model Cortex keep theirs).

**From Stuart's screen recording** (best for apps that need live data or the internet):
`tools/make_media.sh <name> <recording> "<keep ranges>" <preview-start> <still-at>`.
To find pauses worth cutting, measure motion per second (frames that barely change = pause):

```bash
ffmpeg -i rec.mp4 -vf "fps=4,scale=240:-1,format=gray" f/%04d.png
python3 - <<'EOF'
from PIL import Image, ImageChops, ImageStat; import glob
fs=sorted(glob.glob('f/*.png')); prev=None; sec={}
for i,f in enumerate(fs):
    im=Image.open(f)
    if prev: sec.setdefault(i//4,[]).append(ImageStat.Stat(ImageChops.difference(im,prev)).mean[0])
    prev=im
print(' '.join(f'{s}:{max(v):.1f}' for s,v in sorted(sec.items())))   # ~0.5 = still
EOF
```
…then confirm with a timestamped contact sheet:
`ffmpeg -i rec.mp4 -vf "fps=1/3,scale=560:-1,drawtext=text='%{pts\:hms}':x=6:y=6:fontsize=26:fontcolor=yellow:box=1,tile=4x7" -frames:v 1 sheet.jpg`
(keep the "thinking" parts short, cut loading flashes and the idle end).

**Scripted recording with Playwright** (works for static boards with no live data): serve the
board's repo locally (`python3 -m http.server`), open it in a `recordVideo` browser context at
1600×900 with a visible cursor overlay, script the clicks with short pauses, then trim/encode
with ffmpeg. Quantum Observatory must be built first (`npm install && npx vite build
--base=/quantum-observatory/`). Boards that fetch data from the internet (Energy Resilience,
Cyber Attack Earth's live feeds, map tiles) can't be recorded faithfully offline — ask Stuart
for a screen recording instead.

## 13. Testing

See `tests/README.md`. `npm test` runs, on each device in `tests/lib/devices.js`: no sideways
scroll, version stamp, card/article counts and links, toolbar on one line, first-visit view,
info panel on top, WebGL running, carousel fits, arrows turn, front card enlarges and stays on
screen, Watch demo plays (wobbly finger on touch), Open navigates, Fit to screen in both views,
theme remembered, no script errors — plus a no-WebGL fallback run. Results also go to
`tests/out/results.json`; failures leave screenshots in `tests/out/`.

Limits of the rig: it can't reproduce a real phone's GPU or Edge-specific drawing bugs (see
LESSONS #1). When Stuart reports a device-only glitch, ask for a screenshot **with the ⓘ panel's
version visible**, and if possible try Chrome on the same device to separate browser bugs.

## 14. Releasing

1. Make the change (boards.json / page.html → build; or css/js directly).
2. `python3 tools/build.py --bump`
3. `cd tests && npm test` → all PASS; `npm run shots` and look.
4. Add an entry to `docs/CHANGELOG.md`.
5. Package for Stuart: only changed files, zip keeping folders (`index.html` alone if that's all).
6. Tell him the new version string so he can confirm it in the ⓘ panel on each device.
